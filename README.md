# Эмулятор оболочки ОС — вариант №9, этапы 1–2

Учебный проект по дисциплине **«Конфигурационное управление»**.

В проекте реализованы первый и второй этапы практической работы для варианта
№9: графический эмулятор командной оболочки с поддержкой REPL, параметров
запуска и стартовых скриптов.

REPL расшифровывается как **Read–Eval–Print Loop** — цикл чтения команды,
её обработки и вывода результата.


## Требования к системе

Для запуска на Windows необходимы:

- Windows 10 или Windows 11;
- Python версии 3.9 или новее;
- Python Launcher `py` или команда `python` в системной переменной `PATH`;
- библиотека `tkinter`;
- графическая среда Windows.

`tkinter` обычно устанавливается вместе с официальным Python для Windows.
При установке Python с сайта <https://www.python.org/downloads/windows/>
необходимо оставить включённым стандартный компонент **Tcl/Tk and IDLE**.

Внешние Python-зависимости проекту не требуются.

## Запуск в Windows через `run.bat`

1. Распакуйте архив проекта.
2. Откройте папку `shell-emulator-stage1`.
3. Дважды нажмите на файл `run.bat`.

Также можно открыть CMD в папке проекта и выполнить:

```bat
run.bat
```

Скрипт автоматически:

1. переходит в папку проекта;
2. устанавливает `PYTHONPATH` на папку `src`;
3. проверяет наличие команды `py`;
4. запускает `py -3 -m shell_emulator`;
5. если `py` недоступен, запускает `python -m shell_emulator`.



## Работа с графическим интерфейсом

После запуска откроется окно эмулятора.

В нижнее поле вводится команда. Для выполнения команды нажмите `Enter`.

Доступные команды:

```text
ls
ls "folder with spaces"
cd /tmp
cd "folder with spaces"
exit
```

Пример результата:

```text
> ls "folder with spaces"
Команда: ls
Аргументы: folder with spaces
```

Пустая строка не вызывает ошибку.

## Поддерживаемые команды

### `ls`

Команда-заглушка. Она не просматривает содержимое файловой системы, а только
выводит собственное имя и переданный аргумент.

Допускается не более одного аргумента:

```text
> ls documents
Команда: ls
Аргументы: documents
```

При передаче двух аргументов появляется ошибка:

```text
> ls one two
Ошибка: Неверное число аргументов для ls: ожидался максимум 1
```

### `cd`

Команда-заглушка. На первом этапе она не изменяет текущую директорию.

```text
> cd "folder with spaces"
Команда: cd
Аргументы: folder with spaces
```

### `exit`

Завершает работу приложения:

```text
> exit
Завершение работы.
```

Команда `exit` не принимает аргументы:

```text
> exit now
Ошибка: Неверные аргументы: exit не принимает аргументы
```

## Обработка ошибок

### Неизвестная команда

```text
> pwd
Ошибка: Неизвестная команда: pwd
```

### Незакрытая кавычка

```text
> ls "folder
Ошибка: Ошибка разбора: No closing quotation
```

### Слишком много аргументов

```text
> ls one two
Ошибка: Неверное число аргументов для ls: ожидался максимум 1
```

## Запуск тестов в Windows

### CMD

```bat
set PYTHONPATH=src
py -3 -m unittest discover -s tests -v
```

Если команда `py` отсутствует:

```bat
set PYTHONPATH=src
python -m unittest discover -s tests -v
```

### PowerShell

```powershell
$env:PYTHONPATH = "src"
py -3 -m unittest discover -s tests -v
```

Ожидаемый результат — семь успешно пройденных тестов:

```text
Ran 11 tests

OK
```

Тесты проверяют:

- выполнение команды `ls`;
- обработку аргументов в кавычках;
- выполнение команды `cd`;
- неизвестные команды;
- слишком большое количество аргументов;
- команду `exit`;
- ошибку при передаче аргументов в `exit`;
- пустую строку;
- разбор `--vfs-path`;
- разбор `--script-path`;
- значения параметров по умолчанию;
- вывод параметров запуска;
- выполнение команд из стартового скрипта;
- пропуск пустых строк и комментариев;
- остановка стартового скрипта после первой ошибки.


## Запуск тестов в Linux/macOS

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

### Параметры командной строки

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `--vfs-path PATH` | Путь к физическому расположению VFS | `.` |
| `--script-path PATH` | Путь к стартовому скрипту | не задан |

VFS на втором этапе ещё не читается и не изменяется. Путь сохраняется в
конфигурации и выводится для проверки перед подключением файловой системы на
третьем этапе.

### Отладочный вывод

При запуске без скрипта:

```text
Параметры запуска:
  VFS: .
  Стартовый скрипт: не задан
```

При запуске с параметрами:

```text
Параметры запуска:
  VFS: examples/vfs
  Стартовый скрипт: examples/startup/basic.script
```

Отладочные параметры печатаются в консоль, а также отображаются в текстовой
области графического окна.

### Формат стартового скрипта

Стартовый скрипт — обычный текстовый файл UTF-8. Каждая непустая строка
содержит одну команду эмулятора. Строки, начинающиеся с символа `#`,
считаются комментариями и пропускаются.

Пример файла:

```text
# Демонстрационный сценарий
ls "folder with spaces"
cd /tmp
ls documents
```

При выполнении скрипта в окне отображаются и команды, и их результаты:

```text
> ls "folder with spaces"
Команда: ls
Аргументы: folder with spaces
```

Если команда завершилась ошибкой, выполнение немедленно прекращается:

```text
> unknown-command
Ошибка: Неизвестная команда: unknown-command
Скрипт остановлен из-за ошибки.
```

Команды после ошибочной строки не выполняются.

### Запуск второго этапа через `run.bat`

Скрипт `run.bat` передаёт все указанные параметры Python-модулю, поэтому
можно запускать приложение так:

```bat
run.bat --vfs-path "examples\vfs" --script-path "examples\startup\basic.script"
```
